# 2026-09-14

## Automation

Hôm nay tôi học cách thiết lập một workflow GitHub Actions tự động chạy linter và tests mỗi khi có pull request tới nhánh `main`.  
- Sử dụng `actions/setup-node` để cài đặt môi trường Node.js, sau đó chạy `npm ci` và `npm run lint`.  
- Nếu bất kỳ lỗi nào xảy ra, workflow sẽ dừng và thông báo qua comment trên PR, giúp团队尽早发现代码质量问题.  

Cá nhân thấy điều này rất tiện lợi để giảm thiểu việc review thủ công, và tôi định áp dụng cùng cách cho các repo microservice của mình trong tuần tới.


## DevOps

- Học được cách dùng **Argo CD** để tự động hóa deployment bằng GitOps, giúp giảm lỗi con người và tăng tính minh bạch của pipeline.  
- Cấu hình Helm chart với `values.yaml` linh hoạt hơn, hỗ trợ rollout nhanh khi thay đổi cấu hình trên nhiều cluster.  
- Tối ưu hóa build time bằng cách chia nhỏ task trong GitHub Actions và dùng caching layers để giảm tải server.  

Mình sẽ thử triển khai Argo CD vào dự án hiện tại vào tuần tới để kiểm tra khả năng self‑healing.


## Automation
- Hôm nay thử dùng `actions/cache` trong GitHub Actions để cache dependencies của Node.js, giúp giảm time build từ ~3 phút xuống còn ~45 giây. Cần đặt `key` đủ cụ thể (bao gồm hash của lock file), nếu không cache sẽ không hit đúng phiên bản.
- Cá nhân: Mình hay quên config cache cho các workflow cũ, lần này ghi chú lại để ráng áp dụng luôn cho project cá nhân luôn.


## Automation
- Hôm nay setup `direnv` + `.envrc` cho project mới, thay vì phải nhớ `export` từng biến môi trường thì cd vào thư mục là tự load theo `.env`.
- Trong GitHub Actions cần nhớ thêm step `direnv allow` vì mặc nó từ chối file `.envrc` chưa được tin cậy.

Nhận xét cá nhân: Rất tiện, mất đúng 10 phút setup mà đỡ đau đầu đủ kiểu — sẽ áp dụng cho toàn bộ project đang làm luôn.
