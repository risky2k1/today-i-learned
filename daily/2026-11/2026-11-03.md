## Travel Tech

Hôm nay test API của một OTA (Online Travel Agency) lớn thì phát hiện response time của endpoint `GET /hotels/availability` dao động từ 800ms đến 3s tùy thời điểm, nhưng headers trả về luôn có `x-cache: HIT`. Dò sâu ra mới biết CDN cache key của họ **không bao gồm check-in/check-out date** mà chỉ dùng `hotel_id` + `currency`, dẫn đến việc user A search ngày 20/10 nhưng nhận data cached của user B search ngày 25/10. May mà env staging có bật `Cache-Control: no-store` cho param `bust_cache=true` mới reproduce được bug này.

> 💡 *Note cho sau: Khi integrate OTA, luôn phải test cache poisoning bằng cách đổi date/param rồi so sánh response body, đừng tin vào header `x-cache` hay docs của bên thứ 3.*

## DevOps

Hôm nay mình tìm ra cách dùng multi-stage builds trong Docker để giảm đáng kể kích thước image mà vẫn đảm bảo app chạy được normally.

- Dùng stage `FROM node:18-alpine AS builder` để cài dependencies và build code, sau đó dùng một stage runtime nhẹ hơn chỉ để copy kết quả build.
- Chỉ cần lệnh `COPY --from=builder /app/dist ./dist` là có thể copy artifact sang stage final, tránh đưa cả công cụ build vào production image.

Áp dụng ngay cho dự án hiện tại để image size giảm từ ~800MB xuống chỉ còn khoảng 150MB, load nhanh hơn nhiều trên server!
